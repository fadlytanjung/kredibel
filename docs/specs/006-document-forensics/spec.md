## Summary

Deterministic checks that find tampering in single documents and inconsistencies across documents,
each producing evidence-linked findings; a per-document integrity verdict that follows the
corroboration rule; plain-language explanations.

## User stories

### US-006-1: Arithmetic integrity

- **AC-006-1** On S2, `A01_RUNNING_BALANCE_BREAK` is raised exactly once, on the March row whose credit
  was edited, severity `CRITICAL`, with facts `previousBalance`, `credit`, `debit`, `expectedBalance`,
  `printedBalance` and evidence pointing to the row's bbox on its page.
- **AC-006-2** On S2, `A02_OPENING_CLOSING_MISMATCH` is raised for the March statement (`CRITICAL`).
- **AC-006-3** If any value in the failing equation is not `AGREED`, or a witness-only row lies between
  the rows involved, the finding is `E01` (MEDIUM) instead of A01/A02.
- **AC-006-4** `A04_INVOICE_TOTAL_MISMATCH` is raised when an invoice's lines, subtotal, tax and total
  do not add up (fixture), and not on S1 invoices.

### US-006-2: Structure integrity

- **AC-006-5** On S2's March statement: `M01` (producer pattern), `M02` (modified after creation),
  `M03` (2 revisions, page content changed → `HIGH`), `M04` (edited value in a different font, anchored
  to the row).
- **AC-006-6** A single-revision S1 statement raises none of M01–M04.
- **AC-006-7** A revision that only adds an annotation (fixture) → `M03` `MEDIUM`.
- **AC-006-8** An image-only page → `M06_IMAGE_ONLY` (INFO), and M04 is not evaluated.

### US-006-3: Cross-document checks

- **AC-006-9** A statement whose opening ≠ the previous month's closing for the same account →
  `X01_STATEMENT_DISCONTINUITY` (HIGH) anchored to the later statement (fixture; S5 in P1).
- **AC-006-10** A statement whose holder matches none of the applicant's names, aliases or declared
  account holders (`token_set_ratio < 80`) → `X05_ACCOUNT_HOLDER_MISMATCH` (HIGH). The profile-aware
  part of this check and `X06` are built in spec 014.

### US-006-4: Verdicts

- **AC-006-11** Verdicts follow [`docs/08`](../../08-risk-engine.md) §3: S2 March → `TAMPERED`; all
  S1 documents → `CLEAN`; a document with only `E01` → `UNVERIFIABLE`.
- **AC-006-12** `documents.integrity` stores verdict, score and finding IDs; `case.summary.worstVerdict`
  is updated at finalize.

### US-006-5: Explanations

- **AC-006-13** Every finding has an `explanation` ≤ 60 words generated by `finding_explainer` from its
  facts only; on model failure a template explanation is used. Explanations never contain numbers that
  are not in the finding's facts (checked by the grounding guard's number matcher).

### US-006-6: Determinism

- **AC-006-14** Re-running the checks for the same run produces the same finding IDs and no duplicates.
- **AC-006-15** On S1–S3 (recordings), the set of P0 finding codes per document equals `truth.json`.

## Out of scope

`S01`, `V01`, `M05`, revision diff, P1 cross-document checks (010).
